# 路由规则

## 可用路由

### `rag`

用于内部行业报告、消费者洞察、白皮书、历史案例，以及报告正文或图表中的统计结论。

### `web`

用于最新新闻、实时动态、当前政策和其他会随时间变化的公开互联网信息。

### `rag_and_web`

用户明确要求同时结合内部研究与当前互联网信息进行比较、验证或综合分析时使用。

### `sql`

用于项目 MySQL 中的品牌、帖子、达人、Campaign、互动量、投放表现和 ROI 等结构化数据。

### `douyin`

用于抖音指数、搜索指数、内容指数、关联词、地域、年龄、性别、兴趣和 TGI 等平台数据。

- 用户要求查看或分析数据：`action=answer`。
- 用户明确要求采集、抓取或更新数据，并提供了审核后 `research_brief.json`：`action=collect`。
- 用户要求采集但没有提供审核后的任务文件：选择 `clarify`，询问文件路径，不能绕过关键词审核。
- `keywords` 只保留用户明确提供的关键词，不自行增加品牌、竞品或卖点。

### `report`

用于根据品牌研究任务生成完整的抖音投放研究报告，`action=generate_report`。

用户可以提供研究输入 `.xlsx`，也可以提供已经生成的 `research_brief.json`。
如果没有提供可定位的输入文件，选择 `clarify`，询问文件路径。Excel 的字段校验、关键词
生成和审核状态由执行层处理，Router 不得声称已经完成审核。

### `direct`

用于稳定的通用知识和无需外部数据的问题。数学和当前时间也属于此路由，后续可调用简单工具。

### `clarify`

缺少核心主体、关键词、研究任务或比较条件，并且无法安全执行其他路由时使用。

## 数据状态不是意图

Router 只决定用户需要抖音数据，不能猜测数据是否已经存在。执行层负责检查：

- `success`：使用已有数据。
- `partial`：使用成功模块，并披露失败模块。
- `missing`：尚未采集；只有用户明确要求采集时才进入采集流程。
- `failed`：技术失败，可以提示重试。
- `skipped / keyword_not_indexed`：平台未收录，作为数据缺口，不重复采集。

## 查询改写

- 保留专有名词、关键词、年份、数字、比较关系和限制条件。
- 不添加用户没有提供的品牌、竞品、商品、日期或指标。
- `clarify` 时 `retrieval_query` 必须为 `null`；其他路由必须提供非空查询。
